## 本轮审查确定的默认规则

以下由助手根据用户授权确定，作为第一版实现基线，可随后续需求调整。

- 首页和画布统一最多一张参考图；支持 JPEG、PNG、WebP，应用侧限制为 10 MiB，校验实际文件类型。允许删除或替换，上传失败保留提示词并提供重试。
- 提示词去除首尾空白后不能为空，最大 20,000 字符；参考图上传成功后才可发送。Enter 发送、Shift+Enter 换行，中文输入法组词期间不触发发送。
- 首页发送由服务端创建项目、持久化输入并受理生成任务，返回项目与任务标识后跳转画布展示进度；使用请求标识防止刷新或重复点击造成重复收费。新建项目入口创建空项目并进入画布。
- 项目默认名为 Untitled，支持重命名；最近项目展示最近更新的 4 项，全部项目按更新时间倒序每次加载 20 项，通过“加载更多”访问全部。项目卡片进入对应画布，封面取最近成功生成图片。
- 对话面板默认 420px，记忆本机宽度并限制为 320–620px；窄屏采用画布/对话切换，避免挤压画布。
- 默认 Nano Banana 2、1K、1:1；两个模型分别保存项目内配置。模型图标是切换入口。GPT Image2 配置先按真实接口提供分辨率、比例，1K 下可选背景；不显示无接口对应的质量和生成张数控件。配置摘要反映实际发送参数。
- 每次只提交一个生成任务，不通过循环调用实现多图；生成中禁用再次提交。请求被服务端接收后清空已发送草稿，保留历史消息。提交失败保留草稿。
- 从画布选择时进入单图选择状态，点击图片选中，Esc 取消；无图片时禁用入口并提示。复用存储资产，不复制上传；过期签名地址由服务端重新生成。
- 画布支持平移、缩放、图片节点拖动、选择和下载。新结果放置于已有节点右侧，不覆盖旧图；首次结果适配视口，后续不强制重置用户视角。节点位置和视口防抖保存，刷新恢复。
- 生成记录保存提示词、模型、配置快照和参考资产；生成中占位与成功结果共用节点标识。失败显示错误与手动重试；仅重试状态查询，不自动重提收费任务。上游提交结果不明时标记待核实，避免重复提交。
- 等待过久提示“仍在处理”，不能仅因前端超时判定上游失败。刷新后继续查询已有任务。
- 生成结果复制到项目的私有 Storage Bucket 保存；复制失败展示“结果保存失败”，仅重试保存，不重新生图。
- 数据和图片默认仅项目所有者可访问。所有数据表及 Storage 使用 RLS；模型 API 只在服务端调用。
- 第一版完成态提供下载、复用为参考图、手动重新生成；点赞、点踩、分享、复杂图层及图像编辑工具暂不纳入。

## 第一版补充边界

以下为本次需求审查补充的默认规则，不扩大为完整 Lovart 复刻。

- 第一版按画布生图工具推进：每次生成使用本次提示词及至多一张参考图；右侧展示生成历史，不默认将历史文本或图片自动传给模型。需要继续修改时，手动将结果设为参考图。自动规划、多轮语义理解和提示词改写留待后续版本。
- 本地开发优先，先使用现有 Email 登录能力；登录页、邮箱验证回跳、退出登录和会话过期处理纳入基础流程。未登录访问三个业务页面时跳转登录，登录后恢复站内目标地址。
- 无效、缺失或无权访问的 projectId 显示统一的“项目不存在或无权访问”，提供回到项目列表的入口，不泄露其他用户项目信息。
- 每项目保留一个生成历史流；截图中的“新对话”、分享、视图切换等未确认控件不作为第一版功能。
- 并发限制在服务端执行：每用户最多一个未完成生成任务，跨标签页同样生效；这是并发保护，不代表费用预算限制。
- 手动重新生成复用原提示词、配置和参考资产，创建新任务与新节点，保留原结果；提示该操作可能再次计费。
- 第一版不提供项目删除或画布图片永久删除，避免关联历史断裂；删除与回收站作为后续功能。生成资产不自动到期清理。
- 自动保存失败给出可见提示并保留本地草稿；保存使用版本号检测冲突，其他标签页更新时提示刷新，不静默覆盖。
- 用户参考图限制精确定为 10 MiB（10,485,760 bytes）。Supabase 桶的 50 MiB 上限用于生成结果，不等同于参考图上传上限。不得仅依赖前端校验。
- 暂时上传但未绑定项目或生成记录的资产，保留至少 24 小时，再由服务端确认无引用后清理；不删除有效历史资产。
- GPT Image2 配置截图缺失时，沿用 Nano Banana 弹框的视觉结构，按 KIE 已提供接口字段设计，无需阻塞开发。

## 使用范围与费用决策（历史：个人版，已被下方公开上线决策替代）

1. **开放范围（已确认）**：个人自用，不做公开注册入口或多人协作；后端仅允许白名单邮箱账号访问。准入邮箱通过服务端 `APP_OWNER_EMAILS` 配置；当前个人部署使用两个已确认的账号，具体地址不在公开仓库披露；未配置时拒绝业务访问，不能把任意新注册账号当作所有者。两个账号默认按 Supabase 用户 ID 隔离项目、图片和任务，不共享数据。
2. **费用边界（已确认）**：费用由用户自行承担，第一版不做充值、积分或多用户额度系统。用户已授权本轮真实 API 可用性测试，本轮计划三个接口场景各提交一次 1K 任务，不自动重提失败任务。

其余事项不阻塞本地开发：默认采用直接生图而非语言模型 Agent、邮箱登录、本地运行。上线平台、域名和正式邮件服务在部署阶段再确定，不提前索要无关凭据。

## 2026-11-26：连续图片编辑修复

用户反馈“加深天空蓝色”后整张图变为另一张图。实际请求证实第二次没有携带原图，属于手动生图链路缺少连续编辑上下文。

- 请求重试冻结原图或无原图状态，避免后台刷新改变原请求语义。
- 当前为参考图条件生成，不是蒙版局部像素编辑，不能承诺未修改区域像素级不变。
